About & setup

Quick start

  1. Set environment variables. Copy .env.example to .env and fill in the Supabase, Brevo and Telegram keys. Restart the app after changes.
  2. Apply migrations. Run python -m scripts.apply_sql (or, on hosts without a terminal, see the deployment section below).
  3. Configure the sender. Open Settings, set the sender email/name and the public base URL, then save.
  4. Verify deliverability. Open Deliverability to check SPF / DKIM / DMARC and send a test email.
  5. Import contacts and create a list on the Contacts page, then build a campaign from New campaign.

Brevo webhook (opens, clicks, bounces)

In Brevo go to Transactional → Settings → Webhooks, add a webhook for the events you want and paste this URL (replace the token with the value of BREVO_WEBHOOK_SECRET from your .env):

{{ info.webhook_url }}

Events are attributed to campaigns via the X-Mailin-custom header (campaign=…;recipient=…) that every send carries. Without the token the webhook rejects the request.

Magic-link sign-in

Sign-in uses Supabase Auth from the browser. In the Supabase dashboard enable Email → Magic Link and add {{ info.public_base_url }}/auth/callback to the allowed redirect URLs. Only emails listed in AUTH_ALLOWED_EMAILS (comma-separated) may sign in; an empty allowlist denies everyone.

Self-hosting (Windows Server / RDP)

The supported deployment runs every process under one supervisor (waitress + Celery worker/beat + Redis + cloudflared):

  1. Install Python 3.11+, requirements.txt, Redis/Memurai and cloudflared; see deploy/windows/README.md.
  2. Create .env with the Supabase/Brevo/Bird keys and PUBLIC_BASE_URL; keep the four Redis URLs on separate database numbers (the defaults already do).
  3. Migrate and run: python -m scripts.apply_sql then python scripts/run_stack.py. Only waitress on 127.0.0.1 is exposed through the tunnel.

A Redis-less fallback exists for other hosts: set SEND_MODE=cron and schedule python -m app.cron tick every minute (the tick takes a lock, so overlapping jobs cannot double-send).

Operational notes

  • Sending is blocked while the public base URL is localhost — tracking and unsubscribe links must be reachable by recipients.
  • Email content is sent as HTML with an auto-derived plain-text alternative.
  • Pause everything instantly with the kill switch on the Settings page.
  • Alerts (start, completion, progress, errors) are sent to Telegram when configured.
